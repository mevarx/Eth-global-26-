# Arkiv live browser probe: later human operator only

This is a human operator procedure, not evidence of a completed transaction. No BriefMint live publication is verified. Reuse the existing saved R2 draft; no new 0G request is needed or authorized. The integrated browser now checks approval/hash/account/chain, arms once before signing, and saves the RPC broadcast hash before the SDK waits for its receipt.

## First publication on the integrated Next app

1. Open `http://127.0.0.1:3001`, connect the existing owner wallet on **Rabdi 7794095**, and sign in. The wallet needs Rabdi **tGLM** for the transaction fee. Do not press Start Compilation.
2. Open the saved R2 brief. At Release Desk, inspect every public field and approve its exact revision/hash. Remove private facts through the normal draft editor if necessary, then save and approve the new revision instead; never approve an unreviewed revision just to preserve the R2 label.
3. At the publication panel, leave the optional access key empty for the public endpoint or supply the operator's public rate-limit key. Press **Sign publication (approved revision)** once and approve the MetaMask transaction. Wait for backend receipt/readback reconciliation to show `live`; record the entity key and transaction hash. If pending/unknown, use **Reconcile existing attempt**, never sign again.
4. Open `/opportunities`, refresh, select the correct category and Open, and inspect the full record. Independently read it with the commands below; these commands do not use the app API, SQLite, cookies, wallet or 0G. For independence evidence, repeat after the operator stops the app server.

```sh
# Replace this placeholder with the confirmed public entity key.
BRIEFMINT_ENTITY_KEY='0xREPLACE_WITH_CONFIRMED_ENTITY_KEY'
node --import tsx scripts/briefmint-arkiv-reader.ts --get "$BRIEFMINT_ENTITY_KEY" --public-endpoint
node --import tsx scripts/briefmint-arkiv-reader.ts --list --public-endpoint --status open --limit 20
```

5. For the later update transaction, edit public content, Save, approve the new revision, then **Sign update**. For close, change only Candidate status to Closed, Save, approve that exact revision, then **Sign closure**. Each requires a separate operator-approved transaction. Refresh both the selected record and indexed Open/Closed filters after each. Native expiry remains an unverified live gate; patching does not extend it.

## Preconditions

### Explicit fresh demo identity when the original remains unknown

The owner may choose **Create separate demo copy (no AI)** on an approved original with an unknown create and no known hash. This is not nonbroadcast proof or recovery of the original. Accept the visible duplicate-risk warning first: the original transaction may still appear later. The authenticated `POST /api/briefs/:id/publication/copy` binds `expectedRevision`, `publicPayloadHash`, and `acknowledgeDuplicateRisk: true`. It creates at most one separate private copy per source, reuses the genuine model result/evidence without inference, adds a distinct `[demo …]` public title, and requires fresh approval. The original brief, approval and intent are untouched. Private copy provenance never enters Arkiv content.

1. Create the copy explicitly, review its new title and public preview, then approve its own revision/hash at Release Desk.
2. Verify Rabdi 7794095 and the same owner wallet with tGLM. Press Sign publication once; approve only that one new intent.
3. Save the actual broadcast hash and confirmed entity key. If unknown, stop and use recovery rather than another copy or signature.
4. Refresh `/opportunities` and run the independent reader command above against the new entity key. Disclose that the original remains uncertain and this is a separate demo publication.

For an existing `unknown` attempt without a hash, do not press Sign again. The publication panel now accepts a **real known transaction hash** under Recovery. Reconcile sends `recovery: true` to the existing publication/reconcile endpoint: a manual candidate must pass confirmed receipt, Rabdi chain, signer, Arkiv engine, entity owner, canonical payload/hash/revision and expiry checks before it is bound. Invalid, pending or reverted candidates leave the unknown attempt untouched. Once a validated hash is known, receipt/readback observations can be repeated without sending a transaction.

If no hash exists, preserve the lock. Zero latest/pending nonce, unchanged balance and empty explorer/index results do not exclude an unobserved or delayed wallet submission. Collect MetaMask's local RPC failure code/request status and any actual broadcast hash; never provide signatures, seed phrases or private notes. New submissions retain only sanitized RPC phase/code, target, nonce snapshot and calldata hash in browser recovery storage. A nonce snapshot is advisory and never authorizes unlocking. There is no force-unlock endpoint.

Use the currently approved application, supported Node/runtime, Rabdi network (chain 7794095), and an operator-controlled wallet. Verify current `GET /api/briefmint/config` readiness and review the application build/source for the exact transaction flow. Use a separate short-lived synthetic brief, clearly labeled synthetic, with no real/private source notes or contact details. It must have a genuinely compiled ready result, explicit human review of every public field, and explicit owner approval of the exact payload. There is no automatic compute or hidden generation gate. If a ready synthetic result is unavailable, stop; no probe step authorizes paid inference. A helper may use an already ready synthetic brief whose deadline has been separately approved to be short-lived and future-dated. The deadline has to satisfy the API's future/within-seven-days check at create, save, approve and prepare.

The wallet operator must explicitly approve each create, update, close and fee-bearing signature after seeing exact payload and destination. Keep transaction hashes/entity keys as public identifiers only; never record session cookies, signatures, seed phrases, private notes, or access keys in the report. ## Human browser sequence

1. Open the exact local or approved HTTPS application origin; authenticate with the operator wallet using the BriefMint challenge. Confirm `tool_city_session` stays HttpOnly and browser requests use that origin. Sign-in is message authentication, not a publication approval.
2. Select the separately prepared synthetic brief. Inspect its ready output and public preview against `PublicOpportunity` schema v1. Ensure no private note, source identifier, prompt, evidence, or private brief ID appears in public content. Approve the exact displayed hash and revision.
3. Prepare a create intent. `prepare` returns `PublicationIntent`; the private GET shows `publication.pending.state=prepared`. Confirm the intent matches the current revision/hash and connected wallet. Use a main lifecycle record with enough lifetime for update/close; step 8 uses a separate short-lived record. Immediately before signing, revalidate the same intent through `prepare`, inspect its exact public payload, persist the attempt identifier, then arm uncertainty with `reconcile` and null transaction/entity hints. Only this one active attempt may continue to the wallet after the arming response; reloaded unknown state never permits signing. Sign only after explicit operator approval. Persist returned hash/entity identifiers before showing completion. If the wallet reports a possible hash, reconcile it; do not sign again. Rejection after arming remains locked because the backend cannot prove absence of a broadcast.
4. Reconcile via the browser and independently read back by entity key. Compare owner, namespace/schema version, canonical payload and hash, indexed fields, transaction receipt/signer, observed block and expiry. A receipt/entity hint is not evidence until server reconciliation independently confirms it. Save timestamps and redacted evidence.
5. Test public discovery with separate queries using category `writing` and `design`, status `open` and `closed`, minimum budget `0`, a future ISO deadline-after filter, limit `20`, and pagination cursor where returned. Confirm filtering is actually performed by Arkiv query/index support and results are independently checked client-side. Do not count local-only filtering as indexed query proof. The helper's CLI flags are described below.
6. For update, first make an explicitly reviewed and approved changed public revision, prepare `update`, and confirm server read of the fresh base matches its last confirmed hash. Approve the separate wallet transaction. Independently read back and reconcile exact updated payload/hash/revision and owner. If the entity has an external change, stop; resolve manually rather than overwriting.
7. For close, approve a revision whose public status is `closed` and whose other public content matches the confirmed entity. Prepare `close`, confirm the same base checks, approve its separate wallet signature, then independently read/reconcile. A closed record cannot reopen in this MVP.
8. Expiry is a separate short-lived experiment, never the business-deadline filter. Create a separate synthetic record with a genuinely ready result and a separately human-approved future business deadline about 90 seconds ahead, within the seven-day rule. Do this only if compilation/result and approvals are already available in time; do not trigger computation to meet the timer. Verify the SDK maps the server's fixed absolute expiry block to native expiry and independently observe actual expiry block/current block. After expiry, verify the native read and application `refresh`/discovery behavior. A missing record before expiry is not expiry proof; missing after expiry counts only with prior known expiry plus independently observed current block at/after it. Record exact timing and block evidence. If the deadline expires before prepare, the API should reject; do not bypass it.

For each step record application version/commit, origin, UTC timestamp, wallet address (redacted if desired), chain ID, brief revision/hash, operation, transaction hash, entity key, receipt status/signer/block, entity owner, schema/index values, expiry and observed block, and any discrepancies. Preserve screenshots only after checking they reveal no private material or secrets. Reconcile uncertainty before proceeding; an unresolved or reverted transaction cannot be canceled by this probe.

## Independent reader while the backend is stopped

The executable reader uses `scripts/briefmint-arkiv-reader.ts` and `scripts/lib/briefmint-arkiv-reader.ts`, not the app API, database, session, auth cookie or backend. Stop the Next server before running it. Use either a privately exported `ARKIV_ACCESS_KEY` or an ignored `.env.arkiv-reader` containing that name (load it explicitly with `node --env-file=.env.arkiv-reader --import tsx ...`). The alternative `--public-endpoint` flag takes **no URL argument**: it explicitly selects the SDK's rate-limited public Rabdi endpoint with no access key. It never loads another private runtime variable. With no query it prints help and performs no network operations; a query without either access mode fails locally. It prints validated public fields/owner only; treat all returned text as untrusted.

From the repository root, these explicit public-endpoint commands can run with the backend stopped, after a real record exists:

```sh
node --import tsx scripts/briefmint-arkiv-reader.ts --list --public-endpoint --category writing --status open --min-budget-usd-cents 0 --limit 20
node --import tsx scripts/briefmint-arkiv-reader.ts --list --public-endpoint --category design --status closed --deadline-after 1970-01-01T00:00:00.000Z --limit 20
node --import tsx scripts/briefmint-arkiv-reader.ts --get "0x<64-lowercase-hex-entity-key>" --public-endpoint
```

Replace the final quoted placeholder with a real 32-byte entity key. `--list` supports optional `--category writing|design`, `--status open|closed` (default open), `--min-budget-usd-cents N`, `--deadline-after ISO` (default current UTC), `--limit 1..50` (default 20), and `--cursor N` from the prior page. An empty page can still carry a continuation cursor. Pagination spans current blocks and can shift as records change; there is no snapshot guarantee. `--get` accepts the exact lowercase 32-byte entity key. Exit 0 means a successful read, including empty/absent; exit 1 means a sanitized read failure and exit 2 a configuration error. Query output is public data, not proof of successful publication. Native expiry is checked using returned expiry/query blocks, independently of the business deadline threshold. For a specific absent entity, compare its previously recorded native expiry against a current block from the authorized browser/RPC observation.

When `--get` returns `absent`, the real CLI also reports `blockObservedAfterAbsence` from a subsequent independent chain read. This is an upper-bound observation, not a claim that absence was queried at that exact block. Compare it with the expiry recorded when that entity existed, then repeat the entity read after observing that the expiry block has passed. Absence alone remains insufficient, and an unpinned read is not an atomic snapshot. Do not invent a native expiry from elapsed wall time. The first arm of a prepared intent is exclusive; a second null-hint arm returns 409 and must not trigger another wallet prompt. Historical unknown intents also stay locked.
